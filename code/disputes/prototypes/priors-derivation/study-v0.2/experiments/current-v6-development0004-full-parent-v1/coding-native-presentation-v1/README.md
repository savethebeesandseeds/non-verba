# Prospective native presentation prototype

PROTOTYPE, source-only. This folder changes no active pager, admission, pending
request, budget or reading claim. It has made no corpus, coder, tokenizer or model
calls. `presentation.mjs` is pure and has no filesystem or reader access.

The proposed future claim is **complete native-literal presentation plus
machine-verified structure**. It is not full-JSON, full-original, envelope,
stylesheet cascade, rendered image or pixel reading. Complete parent reading and
the existing relevant original-source requirement remain mandatory.

The module adapts the recursive shared-object dictionary in
`lib/representation-replay.mjs`, preserving exact serialized subtree order rather
than canonicalizing object members. `packResponse` / `unpackResponse` reconstruct
the exact compact `JSON.stringify` response bytes. Every value, unknown JSON
field, object-member order and array position survives. Noncanonical JSON,
duplicate-key spellings and reserved literal dictionary-reference shapes fail
closed rather than silently normalizing the input.

`createNativePresentation` accepts only the full parent coding response with the
known V2 native projection, V4 collector and ALL_NATIVE_STYLE_SOURCE_METADATA
schema. New fields or schemas fail before a presentation claim. The review view
contains the complete parent, exact distinct native literal definitions with all
ordered occurrences, and every ordered application to its source range. Duplicate
text at different offsets, zero-output applications, filtered events, origins,
joint whitespace origins/codepoints and unknown CSS values remain distinct.
Machine coverage binds every string occurrence, ordered relationship and object
key; the packed original is retained and independently reconstructed and hashed.
`verifyNativePresentation(originalJSON, presentation)` rederives the view and
coverage before accepting it. Output bounds reject oversized results; no view is
truncated. B's subdivided response schema is not supported by this prototype.

This is a reviewable representation prototype, not an admitted human-review
adapter. Literal occurrence pointers and relationship wiring still repeat in
the review JSON. No real-case speed or size reduction has been measured. Before
an actual review trial, expose the detailed DOM scope, `attribute_adoption` and
`source_origin` qualifiers beside their application references; the current view
keeps some such qualifications in the machine-verified structure. A reader must
not infer semantic irrelevance, effective CSS or visual effects from factoring.

The narrow future method amendment would explicitly authorize this claim for
future, separately admitted requests after the active A0105 scope is closed;
freeze the adapter/schema/verification pins and complete review view; retain the
original prepared response and byte-exact inverse receipt; require the coder to
read the whole parent, all unique native literals and all application/qualifier
relations; and machine-verify repetitive structural/offset data. Preserve all
existing original-source, independent coding, fixed selection, accounting and
partial/context-hold requirements. An unsupported schema or failed coverage check
must stop before any compact-view reading claim. Transport, page acknowledgements
and admission limits still need an ordinary concrete future trial; this folder
does not add an orchestration framework or amend the current protocol.

The 13 declared-synthetic controls passed in the existing managed Debian container
(native exit 0, tool `dc1297`, no skipped tests). They cover exact reconstruction,
every literal/relationship occurrence, repeated decorations, duplicate offsets,
unknown fields/schema, zero-output and whitespace witnesses, surrogate boundaries,
tampering, reserved references and output bounds. The source-copy reservation was
65,536 bytes; actual module/test copies plus an 8,192-byte directory allowance
were 41,504 bytes. The retained source-free run is
`/tmp/nonverba-native-presentation-controls-RDQRrN`.

An independent source-only peer review found no blocker for that narrow prototype
claim and identified the human qualifier and efficiency limits above. No actual
coder response was opened for the review. The case-specific operational endpoint
in [availability-0105/README.md](availability-0105/README.md) is separate.

## Separate future availability triage proposal

A generic operational unavailable-source endpoint needs a separately admitted
evidence rule. Retain the selected case in the denominator of 500; add no meaning,
semantic exclusion, final-reading claim or replacement. Require the own coder's
complete actual admitted parent/native and retained-original text coverage,
ordered paired emission/ACK proofs, exact current source/raw/resource bindings,
and a bounded resource roster showing why potentially required original inputs
remain unread. Preserve an opaque hash-bound own partial declaration and an
explicit statement of the remaining unknown input. A claim about rejected or
header-only extraction additionally requires current pinned technical status;
short selected text alone establishes neither claim. Missing visual content must
not be treated as semantically irrelevant.

Bind each admitted endpoint to the exact case and evidence roster within the
existing clock, cumulative accounting and operation-lock rules. A later generic
validator requires review of those evidence criteria; this prototype only enables
the exact A0105 extension. The uncoded operational outcome cannot satisfy the
formal independent meaningful-500 gate or source-quality gate.
