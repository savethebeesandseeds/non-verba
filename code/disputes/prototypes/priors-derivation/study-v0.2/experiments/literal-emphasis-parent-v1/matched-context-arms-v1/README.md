# Matched Context Arms — PROTOTYPE / UNADOPTED

This isolated experiment prepares four matched input ranges for two previously
exposed cases (0055 then 0047). It follows the completed focal-context projection
and the exploratory 0047 source review. The latter found a focal list continued
outside the focal, and relevant global conditions outside its parent section.

| Arm | Literal scope |
| --- | --- |
| FOCAL_ONLY | Exact original focal span. |
| PARENT_NEIGHBORS_60 | Focal plus at most 60 whitespace-separated source spans in its original parent, initially 30 on each side with unused capacity redistributed. |
| COMPLETE_EXISTING_FRAME | Exactly one complete stored frame containing the full focal; otherwise a typed hold, with no replacement range. |
| FULL_AVAILABLE_NORMALIZED_DOCUMENT | All literal text in the authenticated extraction, as an upper bound of what is available. |

The fourth arm is **not a verified complete contract**. Referenced attachments
that are absent from the admitted file remain unknown. A wider range does not
prove that a condition governs the focal, or that all relevant conditions have
been found.

Each prepared range retains an experimental finite nine-tag encoding and its
matching normalized literal strip. The codec must decode exactly to the source
slice. Identity binds the unchanged original focal, parent, extraction, native
evidence and prior projection. Original native unknowns remain in the
authenticated baseline; the experiment does not claim to recover rendered style
or the missing exhibits. It mints no accepted runtime representation brand.

The pure builder and independent verifier live in arms.mjs. The verifier
reconstructs each range and complete codec result, including the proof for a
resource hold, without calling the builder. No successful clipped output is
permitted. Per-arm and combined byte limits apply to the exact serialized
artifacts and final metadata. Excess payload becomes a typed hold.

input-custody.mjs joins the retained baseline and context projection with their
metadata summaries, source epochs, external execution results, closed clocks and
the exploratory review declaration. It authenticates the original serializations,
including the compact observations file. This pure check grants no file access.

run.mjs and checker.mjs are separate bounded actual entries. A ROOT-issued
admission must pin their source closure and existing Linux Node runtime before
execution. Both rehash the fixed baseline/projection inputs, renew the complete
100-row/29-contract protected guard before each payload read, and verify source,
literal, native and output identities. The checker does not call the arm builder.
The managed container, stored collector, selection and current874 remain intact.

Tokenizer, windowing and aggregation identities are explicitly NOT_OPEN in this
preparation. No model, tokenizer, new manual page or formal coding is authorized
by it. The ten materiality holds remain open, and quality_gate_pass stays false.
The fresh100 and confirmation/replication reserves remain protected. Preparation
success cannot decide the first priors.

The two focused test files contain source-free structural controls. Actual
preparation, readback and final evidence are recorded separately in the study
README once completed; synthetic controls alone are not an actual-case result.
