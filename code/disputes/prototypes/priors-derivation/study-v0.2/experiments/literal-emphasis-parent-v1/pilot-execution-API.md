## Worker protocol

The sole worker entry receives only config path/SHA/bytes as argv. It must use **builtins only**, and must not import project modules or invoke loaders/raw callbacks before `INIT`:

1. Worker sends `HELLO {schema:'pilot-owned-worker-hello-v1',pid,start_ticks}`. Parent independently reads `/proc`, authenticates the forked PID/birth/group, retains its registry and sends `REGISTERED {schema:'pilot-owned-worker-registered-v1',pid,start_ticks,registry_sha256}`.
2. Worker sends `READY {registry_sha256}`. Parent rechecks ownership and admission measurements, then sends `INIT {schema:'pilot-owned-worker-init-v1',phase,config_ref,registry_sha256,source_epoch_sha256,limits,tokenizer_call_allowance:60000}`.
3. Worker must enforce the shared global60k counter **synchronously before every tokenCount**, per-stream20k calls/8192 windows and all loader/planner source/encoding caps. `PROGRESS {case_id,stream_id,total_calls,stream_calls,completed_windows}` is sent every32 calls and at every stream/case end. Parent requires every reported call be attributed to its declared stream, exact monotone deltas of at most32, and all caps. These are authenticated worker instrumentation counters, not independent observation of native tokenizer internals.
4. Before every exclusive write: `WRITE_REQUEST {request_id,case_id,path,encoded_bytes,decoded_bytes,kind}`. Parent performs fresh capacity/RSS/capture/time checks and reserves immutable budgets, then sends `WRITE_GRANTED {request_id}`. After exclusive commit worker sends `WRITE_COMMITTED {request_id,ref:{path,sha256,bytes},decoded_sha256,decoded_bytes}`. Parent bounded-rehashes the actual file and verifies decoded bytes, then sends `WRITE_VERIFIED {request_id}`. No further write before this response. Every message also has its literal `type` field. No text/source/page bodies belong on IPC; metadata messages are capped at65536 serialized bytes.
5. `DONE {status:'COMPLETE'|'HELD',total_calls,completed_ids,failed_ids,remaining_ids,output_refs}` must preserve an exact, disjoint, ordered partition of all original IDs and the exact ordered verified output refs (including decoded hash/bytes). Final call count must equal the received counter. Worker then flushes IPC, disconnects and exits. Missing/failed IPC, missing refs or outputs, retries, substitutions, prefixes and nonzero/signal exits hold the entire attempt.

`WRITE_VERIFIED` is an intermediate receipt. **After owned writers, process group and I/O have joined**, every committed artifact is reopened through the same bounded encoded/decoded SHA/length, UTF8, canonical JSON and gzip validator. Success requires all final readbacks. Late append, replacement, deletion or invalid encoding holds the attempt; the original committed refs remain unchanged alongside final failure/current-file metadata. The guardian does not rewrite, replace or remove a changed artifact. This closes G1 from the independently retained a2f46 review; no claim is made about writes by unrelated processes after terminal verification.

## Boundaries and retained failures

Private capture files are opened before fork, and the stdio pipes exist before child imports. A synchronous private relay stores at most262144 combined bytes. Overflow stops only owned processes and retains the stored prefix with explicit `private_capture_complete:false` and discarded-byte accounting; the entire result is HELD, never a successful prefix. Source words are never forwarded. No inference or source/code meanings are printed. Pages additionally require at most65536 bytes and7500 UTF16 characters for the entire serialized response.

The guardian samples its own plus every observed owned entry/descendant RSS at250ms. An extra OS descendant is forbidden (one worker); parent records its actual lineage/birth, stops the attempt and terminates only identity-matching owned PIDs. Threads within a PID are included in RSS. Previously observed descendants remain accounted for after entry exit. TERM, identity recheck, KILL and bounded joins preserve all existing partials; no unrelated signals, deletion or global cleanup occurs.

Process identity/RSS/children reads fail closed. Only `ENOENT`/`ESRCH` on the process stat establishes disappearance; a missing children file requires a second stat read confirming disappearance. Complete stat fields, positive PID/group/birth, finite nonnegative RSS and unique positive child IDs are validated. Denied/failed reads, malformed or unknown evidence never mean zero RSS or absence, including termination/finally observations. Unknown observations are retained as bounded aggregated records with counts and times; no signal uses an unknown identity. Any such observation holds success and conservatively leaves `owned_absence_verified:false`, even when later exit is known. This closes G2; safe termination cannot be promised while process identity remains unavailable.
